# MW WPF 按钮组件库设计规格

## 目标

建立一套与 MW 自研 WPF 框架真实能力对应的 MasterGo 按钮组件库，让设计师使用容易理解的业务语义和组件属性，同时让 MCP 根据组件结构生成真实的框架代码。

组件库必须明确区分：

- 固定结构组件；
- 可配置的 Variant；
- 允许可变子控件的容器；
- 页面专用的布局结构。

设计组件库不能只根据 Style 名称猜测业务含义。只有真实页面或框架文档明确说明的用途，才能作为已确认的设计师场景；只有结构和视觉证据的 Style，必须标记为“业务用途待确认”。

## 组件库分层

### 1. 基础控件族

先从真实源码、模板和页面用法中盘点按钮相关的 `ControlType` 和模板族。当前确认的范围包括：

- `IconButton` 及其 Style 变体；
- `StatusButton`；
- `ButtonGroup`；
- `ToggleButtonGroup` 和其他 ToggleButton 族（需要继续以源码和真实用法确认）；
- 数字键盘等内部按钮族，但它们与通用业务按钮分开维护。

以下情况必须建立不同的组件族：

- `TargetType` 不同；
- ControlTemplate 不同；
- 状态协议不同；
- 子控件承载契约不同。

如果只是同一个控件的视觉或尺寸差异，可以放在同一个组件集里作为 Variant。

### 2. 组件属性和 Variant

`MW/IconButton` 只暴露真实控件和模板支持的属性：

- 主文本：根据模板对应 `Content` 或 `IconText`；
- 图标：使用受控的图标实例替换；
- 可选快捷标记/状态标记：在框架支持时对应 `TopLeftContent` 和 Boolean 显示属性；
- 图标尺寸：在对应 Style 允许时对应 `IconWidth`、`IconHeight`；
- 视觉样式：使用受控 Variant 映射到真实 Style 键；
- 视觉状态：仅在框架模板支持时提供默认、悬停、按下、选中、禁用等状态。

`IOEnable`、`PageName` 和 `s:Action` 属于工程映射属性，不是设计师可以自由填写的视觉属性。生成代码前必须根据目标项目的真实页面、资源和协议进行查证。

### 3. 容器和嵌套子控件

`MW/MainButtonGrid` 和各类 ButtonGroup 是容器组件，不是固定数量的按钮组件。

每个容器必须定义：

- 允许放入的子组件族；
- 子控件数量是固定还是可变；
- 子控件的顺序和布局规则；
- 合法的插入区域或 Slot；
- 禁止放入的任意图层或控件。

`MW/IconButton` 的内部语义结构保持固定：图标、文本和框架已经支持的标记。设计师如果要加入任意新控件，必须建立新的组合组件，或者先扩展框架模板，不能在生成代码时偷偷把它当成 `s:IconButton` 的额外子控件。

### 4. 使用规范

每个提供给设计师使用的组件或 Variant 都必须包含：

- 用途；
- 适用的页面区域；
- 允许的内容和子组件；
- 错误用法；
- 对应的真实控件和 Style；
- 证据状态：已确认或待确认。

原始 Style 名称只作为实现映射信息保留。设计师看到的名称必须表达已确认的业务语义，不能把 `RightUpDownButtonStyle` 之类的名称直接解释成未经证实的业务动作。

## 设计稿到代码的映射

MCP 转换时必须递归识别每个节点属于哪一类：

1. 框架外壳；
2. 框架容器；
3. 组件实例；
4. 页面专用布局 Frame；
5. 不支持或无法确认的节点。

转换必须保留父子关系，逐层映射到目标项目。

设计坐标只是输入数据：

- MW WPF/XAML 模式优先使用框架的 Style、Template 和布局契约；
- MTSLG IOContorl 模式使用项目确认过的绝对坐标协议。

不能因为设计稿中存在坐标，就默认最终 WPF 代码全部使用绝对定位。

## 完成验收标准

- 每一个公开的组件属性都有真实代码属性或明确的工程映射；
- 每一个 Variant 都能对应已确认的控件、Style 和模板组合；
- 没有目标框架承载能力的组件，不允许提供任意子控件插槽；
- 容器只有在明确子组件类型和布局契约后，才允许子控件数量可变；
- 设计师使用说明中不包含未经证实的业务推断；
- 至少选取一个真实页面实例，验证控件类型、Style、资源键、协议属性和最终布局模式。
